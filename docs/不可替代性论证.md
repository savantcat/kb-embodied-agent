# 不可替代性论证：「为什么非数字人不可」（评分权重 35%）

> 这是全场权重最高、也最容易失分的一项。绝大多数参赛作品会写成"数字人比文本框更亲切"——
> 那是**感受性**论证，评委不买账。要有**约束性**论证：在什么具体条件下，纯文本/纯语音**做不到**。

## 一、场景选型：企业门店 / 展厅的知识问答前台（路线 A）

主角设定：小微企业（烟酒茶叶门店、医疗器械门店、园区政务服务点），
知识资产 = 产品手册 + 售后 SOP + 政策口径 + 报价规则；服务对象 = 到店顾客、中老年客群、双语客户。

## 二、三类"纯文本做不到"的硬约束

| # | 约束 | 纯文本/纯语音为什么失效 | 具身交互为什么必需 |
|---|---|---|---|
| C1 | **输入约束**：到店顾客不习惯在屏幕前打字；中老年客群的键盘输入成本极高 | 文本框方案把交互成本转嫁给用户；语音+纯文本答复又要用户在长文里找答案 | 开口即问；数字人**边说边指**，把答案直接呈现成卡片 |
| C2 | **认知约束**：多步知识（政策申报流程、售后条件）用文字阅读，用户会漏步骤、理解偏差 | 长文本播报 = 单向灌输，无法确认用户是否听懂，无法按用户追问重组 | 数字人可**逐条讲**、可**被打断**、可针对某一条深入；表情与手势承载"重点在哪" |
| C3 | **信任约束**：涉及钱与合规（补贴、报价、售后责任），用户对"一个对话框"天然不信 | 文本框无法传递"我在认真听""我确认过这条依据" | 有形象、有表情、有目光与手势的应答显著提升信任；**同时**把"依据来源"作为字幕/卡片同步展示（可信但不失温度） |

## 三、行动层：从"回答问题"升级为"当场办事"

纯对话方案只能给出文字，用户还得自己填表、自己算价。
本作品在对话中直接**调用工具**（自研 MCP Server）：
查标准条款 → 生成**合规自查清单卡片** → 生成**报价卡** → 复杂情况**转人工**（带上下文与联系方式）。
这是文本对话框做不到的"办事能力"，也对应命题"行动层 = 可执行任务的 Agent 载体"。

## 四、反向论证：为什么不用"手机 App 客服"或"小程序"

- 门店/展厅场景用户**停留时间短**、**不愿装 App、不愿扫码填表**；
- 屏幕是公共的、闲置的（大屏/商显/自助终端），**数字人是"零门槛公共前台"**；
- 与硬件天然匹配：命题方 SDK 支持大屏、商显、机器人——**同一份业务内核可迁移到多种终端**。

## 五、商业化 / 产业化落地路径（评委最关心的一段）

1. **短期（本次参赛即可验证）**：门店数字人前台 —— 已有真实客户场景（企业知识库 + AI 客服产品线在售），
   参赛产出可直接作为"大屏前台"形态交付给现有客群；
2. **中期**：把数字人前台做成**行业模板**（烟草零售 / 医疗器械 / 政务咨询），一份 `scenario.yaml` 切换行业；
3. **长期**：与命题方生态互补——**它提供形象与驱动能力，我们提供企业知识与交付能力**，
   面向小微企业的"知识库 + 数字人前台"打包交付（按年服务收费），可对接命题方的私有化部署能力。
4. **社会价值**：适老化——不会打字、看不清小字的群体也能无障碍获得服务（呼应命题的"普惠无障碍"方向）。

## 六、一句话版本（路演开场与收尾都用它）

> "顾客不会为了问一句'这个能不能退'去装一个 App、去屏幕上打字。
> 我们要做的是让企业自己的知识，**站到顾客面前开口讲**——
> 讲得清、听得懂、被打断也能接住，还能当场把清单和报价递到手上。"
